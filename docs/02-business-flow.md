# 校园资料共享与智能检索平台业务流程设计

## 1. 文档目标

本文基于 `docs/01-requirements.md`，进一步细化平台核心业务流程，重点描述资料上传、管理员审核、搜索、下载、收藏等流程中的关键校验、状态流转和 Redis 参与点。

本文不是接口文档，也不是数据库设计文档，而是后续拆分接口、表结构、Service 业务规则和状态机校验的依据。

## 2. 核心业务状态定义

### 2.1 资料状态

| 状态 | 含义 | 用户可见性 | 是否可搜索 | 是否可下载 |
| --- | --- | --- | --- | --- |
| `PENDING_REVIEW` | 待审核 | 上传者和管理员可见 | 否 | 否 |
| `APPROVED` | 审核通过 | 所有用户可见 | 是 | 是 |
| `REJECTED` | 审核拒绝 | 上传者和管理员可见 | 否 | 否 |
| `OFFLINE` | 已下架 | 管理员可见，上传者可在记录中查看 | 否 | 否 |
| `DELETED` | 已删除 | 普通业务不可见 | 否 | 否 |

### 2.2 文件状态

| 状态 | 含义 | 说明 |
| --- | --- | --- |
| `TEMP` | 临时文件 | 文件正在上传或待确认，不允许被资料引用为正式文件 |
| `STORED` | 已存储 | 文件已保存并生成文件记录，可被资料引用 |
| `REUSED` | 复用文件 | 根据 MD5 命中已存在文件，跳过重复物理存储 |
| `FAILED` | 存储失败 | 文件校验或保存失败，需要终止上传流程 |

### 2.3 关键数据对象

| 对象 | 作用 |
| --- | --- |
| `resource_file` | 保存文件物理信息，例如 MD5、文件大小、存储路径、文件类型 |
| `resource` | 保存资料业务信息，例如标题、课程、标签、审核状态、上传者 |
| `review_log` | 保存审核日志，例如操作人、原状态、新状态、审核意见 |
| `download_record` | 保存用户下载行为，用于审计和个人下载记录 |
| `favorite_record` | 保存用户收藏关系，防止重复收藏 |

## 3. 用户上传资料流程

### 3.1 文字流程

1. 学生用户携带 JWT 发起上传请求，提交文件和资料元数据。
2. 后端校验登录态、用户状态和上传权限。
3. 后端执行上传限流，避免同一用户短时间批量上传垃圾资料。
4. 校验资料元数据：
   - 资料标题不能为空。
   - 课程名称不能为空。
   - 资料类型必须属于系统允许范围。
   - 标签数量和长度不能超过限制。
5. 校验文件基础信息：
   - 文件不能为空。
   - 文件大小不能超过配置上限。
   - 文件扩展名必须在白名单内，例如 `pdf`、`doc`、`docx`、`ppt`、`pptx`、`zip`。
   - MIME 类型需要与扩展名基本匹配。
6. 后端以流式方式计算文件 MD5，同时可记录文件大小，避免一次性读取大文件到内存。
7. 根据 `md5 + file_size` 查询 `resource_file`：
   - 如果已存在相同文件，则复用已有文件记录，不再重复保存物理文件。
   - 如果不存在相同文件，则保存文件到本地存储或对象存储，并创建新的文件记录。
8. 判断是否为业务重复提交：
   - 如果同一用户已经上传过相同 `file_id` 且存在 `PENDING_REVIEW` 或 `APPROVED` 的资料，可拒绝重复提交。
   - 如果相同文件用于不同课程或不同资料说明，可允许创建新的资料记录，但复用同一份物理文件。
9. 创建 `resource` 资料记录：
   - 关联 `file_id`。
   - 保存标题、课程、类型、标签、简介、上传用户。
   - 初始状态设置为 `PENDING_REVIEW`。
10. 返回上传成功结果，提示资料已进入待审核状态。

### 3.2 上传流程状态表

| 阶段 | 前置状态 | 触发动作 | 后置状态 | 失败处理 |
| --- | --- | --- | --- | --- |
| 登录校验 | 未校验 | 解析 JWT 并查询用户状态 | 已登录 | 返回未登录或用户禁用错误 |
| 参数校验 | 已登录 | 校验资料标题、课程、类型、标签 | 参数合法 | 返回参数错误 |
| 文件校验 | 参数合法 | 校验大小、扩展名、MIME | 文件合法 | 返回文件不合法错误 |
| MD5 计算 | 文件合法 | 流式计算 MD5 | 已生成 MD5 | 返回文件读取失败 |
| 重复文件判断 | 已生成 MD5 | 查询 `resource_file` | 命中复用或未命中 | 查询失败则终止 |
| 文件保存 | 未命中文件 | 保存到存储系统 | `STORED` | 删除临时文件并终止 |
| 文件复用 | 命中文件 | 复用已有 `file_id` | `REUSED` | 无需重复存储 |
| 资料创建 | `STORED` 或 `REUSED` | 插入 `resource` 记录 | `PENDING_REVIEW` | 数据库失败时清理新保存文件 |

### 3.3 上传后的资料状态流转表

| 当前状态 | 操作 | 目标状态 | 是否允许 | 说明 |
| --- | --- | --- | --- | --- |
| 无资料记录 | 创建资料 | `PENDING_REVIEW` | 是 | 上传成功后默认进入待审核 |
| `PENDING_REVIEW` | 用户重复提交同一文件 | `PENDING_REVIEW` | 否 | 应提示已有待审核资料 |
| `REJECTED` | 用户重新上传修改后的资料 | `PENDING_REVIEW` | 是 | 建议创建新资料记录或新审核版本 |
| `APPROVED` | 用户再次上传同一文件 | `PENDING_REVIEW` | 视规则而定 | 同课程同标题建议拒绝，不同课程可允许复用文件 |

## 4. 管理员审核流程

### 4.1 文字流程

1. 管理员携带 JWT 访问审核接口。
2. 后端校验登录态、用户状态和管理员角色。
3. 管理员查询待审核资料列表，只展示 `PENDING_REVIEW` 状态资料。
4. 管理员查看资料详情和文件基础信息。
5. 管理员执行审核动作：
   - 审核通过：资料状态从 `PENDING_REVIEW` 变为 `APPROVED`。
   - 审核拒绝：资料状态从 `PENDING_REVIEW` 变为 `REJECTED`，必须填写拒绝原因。
   - 下架资料：资料状态从 `APPROVED` 变为 `OFFLINE`，必须填写下架原因。
6. 后端在状态变更前执行状态机校验，禁止非法状态转换。
7. 状态变更成功后写入 `review_log`，记录操作人、操作类型、原状态、新状态、原因和操作时间。
8. 如果资料审核通过，后续可触发搜索索引创建和排行榜初始化。
9. 如果资料被下架，后续需要从搜索结果和排行榜中移除或降权。

### 4.2 审核动作状态流转表

| 当前状态 | 管理员操作 | 目标状态 | 是否允许 | 必填原因 | 业务影响 |
| --- | --- | --- | --- | --- | --- |
| `PENDING_REVIEW` | 审核通过 | `APPROVED` | 是 | 否 | 资料可搜索、可下载 |
| `PENDING_REVIEW` | 审核拒绝 | `REJECTED` | 是 | 是 | 资料不可搜索、不可下载，上传者可查看原因 |
| `APPROVED` | 下架资料 | `OFFLINE` | 是 | 是 | 资料从搜索和下载范围移除 |
| `REJECTED` | 审核通过 | `APPROVED` | 否 | - | 拒绝后不能直接通过，需要用户重新提交 |
| `REJECTED` | 下架资料 | `OFFLINE` | 否 | - | 已拒绝资料本身未发布，无需下架 |
| `OFFLINE` | 审核通过 | `APPROVED` | 否 | - | 下架资料不能直接恢复，建议走重新审核流程 |
| `APPROVED` | 审核拒绝 | `REJECTED` | 否 | - | 已发布资料不能改成拒绝，只能下架 |
| `PENDING_REVIEW` | 下架资料 | `OFFLINE` | 否 | - | 待审核资料尚未发布，不能下架 |

### 4.3 非法状态转换处理

出现非法状态转换时，系统必须拒绝请求，并返回明确错误，例如：

```text
当前资料状态为 APPROVED，不允许执行 REVIEW_REJECT 操作。
```

状态机校验建议集中在 `ReviewService` 或独立的 `ResourceStatusMachine` 中实现，避免散落在 Controller 或 Mapper 中。

## 5. 用户搜索资料流程

### 5.1 文字流程

1. 用户输入关键词，并可选择课程、资料类型、标签、排序方式等筛选条件。
2. 后端校验搜索参数：
   - 关键词长度不能超过限制。
   - 分页参数必须合法。
   - 排序字段必须在白名单内。
3. 后端执行搜索限流，防止高频爬取和恶意刷热门词。
4. 后端记录搜索关键词：
   - 过滤空关键词。
   - 对关键词进行 trim、统一大小写等归一化处理。
   - 可过滤敏感词和无意义词。
5. 后端更新 Redis 热门搜索词排行榜：
   - 使用 Redis ZSet。
   - Key 示例：`ranking:search:keyword:daily`。
   - Score 每次搜索递增 1。
6. 执行资料搜索：
   - 必须强制添加 `status = APPROVED` 条件。
   - 游客和学生都不能搜索到 `PENDING_REVIEW`、`REJECTED`、`OFFLINE` 状态资料。
   - 管理员后台审核列表不复用普通搜索接口，避免越权泄露。
7. 返回分页搜索结果。

### 5.2 搜索流程状态表

| 阶段 | 输入状态 | 处理动作 | 输出状态 | 说明 |
| --- | --- | --- | --- | --- |
| 参数接收 | 原始搜索条件 | 校验关键词、分页、排序字段 | 合法搜索条件 | 非法参数直接返回错误 |
| 限流检查 | 合法搜索条件 | 按 IP 或用户 ID 限流 | 允许搜索 | 超限返回请求过于频繁 |
| 关键词归一化 | 允许搜索 | trim、大小写统一、过滤无效词 | 标准关键词 | 空关键词可不进入热门词统计 |
| 热词统计 | 标准关键词 | Redis ZSet 分数递增 | 热门搜索词更新 | 不阻塞主搜索流程 |
| 权限过滤 | 搜索条件 | 强制追加 `APPROVED` 状态 | 安全查询条件 | 避免搜出未审核资料 |
| 执行搜索 | 安全查询条件 | MySQL 或 Elasticsearch 查询 | 搜索结果 | 后续可切换搜索引擎 |

### 5.3 搜索状态约束表

| 资料状态 | 是否出现在普通搜索结果 | 原因 |
| --- | --- | --- |
| `PENDING_REVIEW` | 否 | 资料尚未审核，质量和合规性未确认 |
| `APPROVED` | 是 | 已通过审核，可公开展示 |
| `REJECTED` | 否 | 审核拒绝，不允许公开 |
| `OFFLINE` | 否 | 已下架，不允许继续传播 |
| `DELETED` | 否 | 已删除，不应出现在业务查询中 |

## 6. 用户下载资料流程

### 6.1 文字流程

1. 用户携带 JWT 请求下载资料。
2. 后端校验登录态：
   - 未登录用户不允许下载。
   - Token 无效或已进入 Redis 黑名单时拒绝下载。
   - 用户被禁用时拒绝下载。
3. 后端查询资料记录，校验资料状态必须为 `APPROVED`。
4. 后端执行下载限流：
   - 按用户 ID 限制单位时间下载次数。
   - 按 IP 限制单位时间下载次数。
   - 可按 `user_id + resource_id` 限制短时间重复下载同一资料。
5. 后端校验文件是否存在且可访问。
6. 创建 `download_record` 下载记录，记录用户、资料、IP、User-Agent、下载时间。
7. 返回文件流或临时下载地址。
8. 下载成功后更新 Redis 统计：
   - Redis Hash 记录下载增量，Key 示例：`stats:resource:download:delta`。
   - Redis ZSet 更新热门资料排行，Key 示例：`ranking:resource:hot`。
   - 可设置短期去重 Key，避免同一用户反复刷新导致下载量虚高。
9. 定时任务批量同步 Redis 下载增量到 MySQL：
   - 定时读取 Hash 中的所有 `resource_id -> delta`。
   - 批量更新 `resource.download_count`。
   - 同步成功后删除或清零对应 Redis 增量。
   - 同步失败时保留 Redis 数据，等待下一轮重试。

### 6.2 下载流程状态表

| 阶段 | 前置状态 | 触发动作 | 后置状态 | 失败处理 |
| --- | --- | --- | --- | --- |
| 登录校验 | 未校验 | 解析 JWT | 已登录 | 返回未登录 |
| 资料校验 | 已登录 | 查询资料并校验状态 | 资料可下载 | 非 `APPROVED` 则拒绝 |
| 限流校验 | 资料可下载 | Redis 限流脚本 | 允许下载 | 超限返回请求过于频繁 |
| 文件校验 | 允许下载 | 检查文件路径或对象存储 Key | 文件可访问 | 文件不存在则返回资源异常 |
| 记录下载 | 文件可访问 | 插入 `download_record` | 下载已记录 | 失败时可终止或异步补偿 |
| 返回文件 | 下载已记录 | 输出文件流或临时 URL | 下载响应已返回 | 输出失败记录异常日志 |
| Redis 统计 | 下载成功 | 增加下载增量和热度分 | 统计已更新 | Redis 异常记录日志并可降级 |
| 定时落库 | Redis 有增量 | 批量同步 MySQL | 数据库下载数更新 | 失败保留 Redis 增量 |

### 6.3 下载相关状态约束表

| 资料状态 | 是否允许下载 | 说明 |
| --- | --- | --- |
| `PENDING_REVIEW` | 否 | 待审核资料不能被下载 |
| `APPROVED` | 是 | 通过审核后允许下载 |
| `REJECTED` | 否 | 审核拒绝资料不能被下载 |
| `OFFLINE` | 否 | 下架资料不能被下载 |
| `DELETED` | 否 | 删除资料不能被下载 |

### 6.4 Redis 下载统计同步表

| Redis 数据 | 类型 | 写入时机 | MySQL 同步目标 | 同步策略 |
| --- | --- | --- | --- | --- |
| `stats:resource:download:delta` | Hash | 下载成功后 | `resource.download_count` | 定时批量累加 |
| `ranking:resource:hot` | ZSet | 下载、收藏、浏览后 | 可选排行榜快照表 | 实时查询，定时快照 |
| `dedup:download:{userId}:{resourceId}` | String | 下载成功后 | 无 | 短 TTL，用于重复下载去重 |

## 7. 收藏资料流程

### 7.1 文字流程

1. 学生用户携带 JWT 请求收藏资料。
2. 后端校验登录态和用户状态。
3. 查询资料记录，要求资料状态为 `APPROVED`。
4. 判断是否已收藏：
   - 优先查询 Redis Set，例如 `user:favorites:{userId}`。
   - Redis 未命中时查询 `favorite_record`。
5. 如果已经收藏，则直接返回“已收藏”，不重复插入收藏记录。
6. 如果未收藏，则插入 `favorite_record`。
7. 更新资料收藏数：
   - 可直接更新 MySQL。
   - 也可使用 Redis 计数缓冲，后续批量同步。
8. 更新资料热度分数：
   - Redis ZSet `ranking:resource:hot` 增加收藏权重。
   - 收藏行为的权重通常低于下载或可配置，例如收藏加 3 分。
9. 将资料 ID 加入用户收藏 Redis Set，提升后续判断速度。

### 7.2 取消收藏流程

1. 学生用户请求取消收藏。
2. 后端校验登录态和资料存在性。
3. 查询收藏关系。
4. 如果收藏关系不存在，则返回成功，保证接口幂等。
5. 如果收藏关系存在，则删除或软删除收藏记录。
6. 更新资料收藏数。
7. Redis ZSet 中降低资料热度分数。
8. 从用户收藏 Redis Set 中移除资料 ID。

### 7.3 收藏流程状态表

| 当前状态 | 用户操作 | 目标状态 | 是否允许 | 业务影响 |
| --- | --- | --- | --- | --- |
| 未收藏 | 收藏 | 已收藏 | 是 | 创建收藏记录，增加收藏数和热度分 |
| 已收藏 | 收藏 | 已收藏 | 是 | 幂等返回，不重复增加收藏数 |
| 已收藏 | 取消收藏 | 未收藏 | 是 | 删除收藏关系，减少收藏数和热度分 |
| 未收藏 | 取消收藏 | 未收藏 | 是 | 幂等返回，不报错 |

### 7.4 收藏资料状态约束表

| 资料状态 | 是否允许收藏 | 是否允许取消收藏 | 说明 |
| --- | --- | --- | --- |
| `PENDING_REVIEW` | 否 | 是 | 不能收藏未审核资料，但可清理历史异常收藏 |
| `APPROVED` | 是 | 是 | 正常收藏和取消收藏 |
| `REJECTED` | 否 | 是 | 不能收藏拒绝资料 |
| `OFFLINE` | 否 | 是 | 下架后不允许新增收藏，但允许用户取消 |
| `DELETED` | 否 | 是 | 删除后不允许新增收藏 |

### 7.5 收藏热度更新表

| 行为 | Redis Key | 数据类型 | 分数变化建议 | 说明 |
| --- | --- | --- | --- | --- |
| 收藏资料 | `ranking:resource:hot` | ZSet | `+3` | 表示用户对资料有持续关注 |
| 取消收藏 | `ranking:resource:hot` | ZSet | `-3` | 避免热度虚高 |
| 下载资料 | `ranking:resource:hot` | ZSet | `+5` | 下载行为权重更高 |
| 浏览资料 | `ranking:resource:hot` | ZSet | `+1` | 浏览权重较低，可选实现 |

## 8. 总体状态流转总表

| 业务动作 | 允许的起始状态 | 目标状态 | 核心校验 |
| --- | --- | --- | --- |
| 上传资料 | 无资料记录 | `PENDING_REVIEW` | 登录、上传限流、文件校验、MD5 去重 |
| 审核通过 | `PENDING_REVIEW` | `APPROVED` | 管理员权限、状态机校验 |
| 审核拒绝 | `PENDING_REVIEW` | `REJECTED` | 管理员权限、拒绝原因 |
| 下架资料 | `APPROVED` | `OFFLINE` | 管理员权限、下架原因 |
| 搜索资料 | `APPROVED` | 状态不变 | 强制过滤非公开状态 |
| 下载资料 | `APPROVED` | 状态不变 | 登录、限流、文件可访问 |
| 收藏资料 | `APPROVED` | 状态不变 | 登录、防重复收藏 |
| 取消收藏 | 任意可见记录 | 状态不变 | 登录、幂等处理 |

## 9. 设计注意事项

- 文件 MD5 用于物理文件去重，不等于业务资料一定重复。
- 资料状态转换必须集中校验，禁止接口绕过状态机直接更新状态字段。
- 普通搜索接口必须固定过滤 `APPROVED`，管理员审核查询应使用独立接口。
- 下载次数不要每次同步写 MySQL，应优先写 Redis，再由定时任务批量落库。
- Redis 统计失败不能影响文件下载主流程，但需要记录日志并支持后续补偿。
- 收藏和取消收藏需要保证幂等，避免用户重复点击造成计数错误。
- 后续引入 Elasticsearch 或 RocketMQ 时，应复用本流程中的业务事件和状态边界，不改变核心业务规则。
