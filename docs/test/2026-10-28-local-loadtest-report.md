在已取消的收藏关系上，同账号/同资料同时发送 20 个 POST：11 个 HTTP 200/code=0，9 个 HTTP 400/code=40901。预期所有重复收藏按幂等成功处理，因此本项失败；没有放宽断言或自动重试掩盖。

该轮数据库资料收藏计数为 1，与有效收藏数量一致，全库收藏计数聚合差异为 0；清回未收藏基线后差异仍为 0。该问题是并发响应语义缺陷，本次未观察到收藏关系重复或计数破坏，独立的只读容量实验可以继续。短验证全部发生在搜索 20 线程档的升压排除窗口内，不计入其稳态成绩。

代码位置：[FavoriteServiceImpl.activateFavoriteInTransaction](../../campus-resource-platform/src/main/java/com/john/campus/service/impl/FavoriteServiceImpl.java)。当前恢复操作条件 UPDATE 影响行数为 0 后，在同一事务再次普通 SELECT，未读到已恢复状态时抛 40901。结合本轮 RR 隔离和实际触发分支，推断竞争失败后重读旧快照是主要原因，仍需修复后的并发回归确认；MySQL 对同事务一致性读快照的说明见 [官方隔离级别文档](https://dev.mysql.com/doc/refman/8.0/en/innodb-transaction-isolation-levels.html)。

后续修复应评估把竞争失败的幂等确认移到事务外的新快照或使用适当的当前读，并增加真实 MySQL 并发回归；不能仅调整压测预期把 40901 当成功。本轮范围为压测与文档，不修改该业务实现。
