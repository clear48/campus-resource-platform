# 校园资料共享与智能检索平台前端需求文档

## 1. 文档目标

本文档基于当前后端需求、业务流程、API、Redis 设计和项目进度文档，定义一套用于演示后端能力的轻量前端需求。

前端的唯一定位是：**为当前后端项目提供可操作、可讲解、可验证的演示界面**。前端不作为独立产品建设，不追求复杂视觉效果，也不为尚未实现的后端能力预做重型工程设计。

本文中的接口状态以当前真实后端代码和 `docs/04-api-doc.md` 为准。规划中但尚未实现的接口，不进入首版页面调用范围。

## 2. 产品定位与设计原则

### 2.1 前端定位

- 面向 Java 后端项目演示、功能联调和面试讲解。
- 重点展示“请求如何触发后端业务链路，以及后端如何返回结果”。
- 页面只需清晰、可用、便于演示，不要求商业产品级视觉设计。
- 首版同时支持游客浏览、普通用户操作和管理员操作，但重点区分普通用户页面与管理员页面。

### 2.2 轻量实现原则

- 使用简单的单页应用即可；可选 Vue 3 + Vite + Axios，也可使用同等轻量方案。
- 使用固定路由和固定导航，不实现后端驱动的动态菜单。
- 登录信息只需保存 JWT 和当前用户基本信息，不引入复杂状态管理框架。
- 通用请求层只负责基础地址、JWT 请求头、统一响应解包和通用错误提示。
- 使用普通表格、表单、分页、标签、弹窗和提示消息完成交互。
- 页面布局以桌面端演示为主，只做基础自适应，不追求复杂响应式设计。

### 2.3 角色边界

| 角色 | 页面范围 | 说明 |
| --- | --- | --- |
| 游客 | 首页、资料搜索、公开资料详情、登录、注册 | 只能访问公开数据，不能上传、收藏和下载 |
| 普通用户 | 游客页面 + 上传资料、我的上传、我的收藏、我的下载、个人信息 | 登录后携带 JWT 调用受保护接口 |
| 管理员 | 普通登录能力 + 审核管理、发布资料管理、排行榜运维 | 管理接口要求后端校验 `role = 2` |

前端可根据当前用户角色显示或隐藏管理员入口，但这只是界面引导，不是安全边界。真实权限必须由后端 JWT 拦截器和 Service 层角色校验保证。

## 3. 全局交互约定

### 3.1 登录态与请求头

- 登录成功后保存后端返回的 JWT。
- 受保护请求统一携带：`Authorization: Bearer {token}`。
- 页面初始化时可调用 `GET /api/v1/users/me` 恢复当前用户信息和角色。
- 退出登录必须先调用后端退出接口，成功后再清理本地 JWT，借此演示 Redis Token 黑名单，而不是只做前端本地退出。

### 3.2 统一响应与异常展示

- 普通 JSON 接口按后端统一结构 `code/message/data/traceId` 解包。
- `code = 0` 视为成功；其他业务码统一展示后端 `message`。
- 开发演示模式下，可在错误提示或请求结果区域展示 `traceId`，体现统一异常处理和链路定位能力。
- `40101`、`40102`：提示登录失效并跳转登录页。
- `40301`：提示权限不足，不自动伪装成页面不存在。
- `40901`：直接展示非法状态流转、资料状态不允许等业务冲突信息。
- `42901`：展示下载频率过高提示；不要在前端模拟一个与后端不一致的限流倒计时。
- 文件流接口 `GET /api/v1/download-records/{downloadRecordId}/file` 不走统一 JSON 包装，前端应按二进制文件处理，并读取响应头中的文件名。

### 3.3 页面状态

每个数据页面只需要以下基础状态：

- 加载中；
- 空数据；
- 请求失败与重试；
- 分页；
- 操作成功提示；
- 按钮提交中与防重复点击。

不建立全局复杂状态机。资料状态统一展示为：`0 待审核`、`1 已通过`、`2 已拒绝`、`3 已下架`、`4 已删除`。

## 5. 公共与普通用户页面需求

### 5.1 登录页

**页面内容**

- 用户名、密码输入框；
- 登录按钮；
- 注册页入口；
- 登录失败信息；
- 可选的“显示接口结果”折叠区，用于演示 `code/message/traceId`。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/auth/login` | 校验账号密码并签发 JWT |
| `GET /api/v1/users/me` | 登录后获取当前用户信息和角色，也用于刷新页面恢复会话 |

**要展示的后端技术亮点**

- BCrypt 密码校验；
- JWT 无状态认证；
- JWT 拦截器解析用户身份；
- 用户禁用状态校验；
- 统一响应、错误码和全局异常处理。

登录限流目前尚未实现，页面不得宣称登录接口已经具备 Redis 限流。

### 5.2 注册页

**页面内容**

- 用户名、密码、昵称、邮箱、手机号表单；
- 前端只做必填、长度和格式等即时提示，最终规则以后端校验为准；
- 注册成功后跳转登录页。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/auth/register` | 创建用户账号 |

**要展示的后端技术亮点**

- Bean Validation 参数校验；
- BCrypt 密码加密存储；
- 用户名、邮箱或手机号重复校验；
- 数据库唯一约束与统一业务异常。

### 5.3 首页

**页面内容**

- 简单搜索框，提交后进入资料搜索页；
- 热门资料 Top 10 列表；
- 热门搜索词 Top 10，可点击后进入对应搜索结果；
- 日榜、周榜、月榜、总榜切换；
- 热门资料仅使用列表或卡片展示，不使用复杂图表。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/rankings/resources/hot?limit=10&period={period}` | 查询热门资料；`period` 支持 `daily/weekly/monthly/all` |
| `GET /api/v1/rankings/search-keywords/hot?limit=10&period={period}` | 查询热门搜索词；支持日、周、月周期 |

**要展示的后端技术亮点**

- Redis ZSet 实时 Top N 排行；
- 热门资料返回前再次由 MySQL 校验 `APPROVED` 状态，避免脏成员泄露下架资料；
- Redis 不可用时热门资料降级到 MySQL `hot_score` 快照；
- 热门搜索词属于旁路运营数据，Redis 异常可降级为空列表；
- 下载、收藏、审核行为对排行榜的实时联动；
- 日、周、月、总榜的周期语义隔离。

### 5.4 资料搜索页

**页面内容**

- 关键词；
- 分类、课程名、资料类型、标签筛选；
- 创建时间、下载量、收藏量、热度排序；
- 升序、降序切换；
- 分页结果；
- 点击结果进入资料详情。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/categories?parentId={parentId}` | 加载启用分类 |
| `GET /api/v1/search/resources` | 按关键词、分类、课程、类型、标签、排序和分页条件检索资料 |

**要展示的后端技术亮点**

- MySQL 模糊检索与组合筛选；
- SQL 固定过滤 `status = APPROVED`，公开可见性不依赖前端参数；
- 排序字段白名单映射，防止把前端参数直接拼接进 SQL；
- `PageResult` 统一分页模型；
- 非空搜索词成功后写入 Redis 日、周、月热门搜索词 ZSet；
- Redis 热词统计失败不阻断搜索主流程。

当前未实现 `GET /api/v1/search/suggestions`，因此首版搜索框不做联想建议、自动补全和高亮搜索。

### 5.5 资料详情页

**页面内容**

- 标题、课程、分类、类型、标签、简介、上传者、创建时间；
- 下载量、收藏量、热度分；
- 收藏/取消收藏按钮；
- 下载按钮；
- 未登录时点击收藏或下载，引导前往登录页。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/resources/{resourceId}` | 获取公开资料详情，只允许访问已通过资料 |
| `GET /api/v1/resources/{resourceId}/favorite-status` | 登录后查询当前用户是否已收藏 |
| `POST /api/v1/resources/{resourceId}/favorites` | 收藏资料 |
| `DELETE /api/v1/resources/{resourceId}/favorites` | 取消收藏 |
| `POST /api/v1/resources/{resourceId}/download-records` | 创建下载记录并执行下载权限、限流和去重统计 |
| `GET /api/v1/download-records/{downloadRecordId}/file` | 根据上一步返回的记录 ID 获取文件流 |

**要展示的后端技术亮点**

- 资料状态控制：非 `APPROVED` 资料不能通过公开详情访问、收藏或下载；
- 收藏关系 MySQL 唯一索引、幂等处理和收藏数原子更新；
- Redis Set 加速“是否已收藏”判断，缓存异常时回源 MySQL；
- 收藏事务提交后再更新 Redis 排行榜，避免数据库回滚造成脏热度；
- 下载按用户和 IP 双维度执行 Redis ZSet 滑动窗口限流，并通过 Lua 保证原子性；
- 同一用户对同一资料 10 分钟内重复下载仍允许获取文件，但不重复增加下载量和热度；
- 下载量先写 Redis Hash 增量，再由定时任务批量同步 MySQL；
- 文件流读取包含归属校验、路径穿越防护和中文文件名编码。

下载必须严格执行“两步调用”：先创建下载记录，再使用返回的 `downloadRecordId` 请求文件流。前端不能直接拼接文件存储路径。

### 5.6 上传资料页

**页面内容**

- 文件选择；
- 文件 MD5 计算进度；
- 标题、课程名称、分类、资料类型、标签、简介表单；
- 上传与创建资料的分步状态提示；
- 秒传命中时显示“文件已存在，复用已有文件”；
- 创建成功后提示“资料已进入待审核状态”。

**对应后端接口与调用顺序**

| 顺序 | 接口 | 用途 |
| --- | --- | --- |
| 1 | `GET /api/v1/categories?parentId={parentId}` | 加载可选分类 |
| 2 | `GET /api/v1/files/check?fileMd5={md5}&fileSize={size}` | 使用 MD5 和文件大小执行上传预检 |
| 3A | `POST /api/v1/files` | 未命中时以 `multipart/form-data` 上传物理文件并获取 `fileId` |
| 3B | 无需上传 | 命中秒传时直接复用预检返回的 `fileId` |
| 4 | `POST /api/v1/resources` | 提交 `fileId` 和资料元数据，创建待审核资料 |

**要展示的后端技术亮点**

- 物理文件 `file_info` 与业务资料 `resource` 解耦；
- `file_md5 + file_size` 去重，Redis 缓存与数据库唯一约束共同支撑秒传；
- 文件大小、扩展名、MIME 类型和文件名安全校验；
- 使用安全存储文件名，避免直接使用用户原始文件名；
- 文件已保存但数据库写入失败时执行补偿清理；
- 文件、分类状态和重复资料提交由 Service 层兜底校验；
- 标签去空白、去重、保序；
- 新资料统一进入 `PENDING_REVIEW`，不能绕过审核直接公开。

前端计算 MD5 只用于减少无效上传和演示秒传，后端仍是文件合法性与业务一致性的最终责任方。

### 5.7 我的上传页

**页面内容**

- 按全部、待审核、已通过、已拒绝、已下架筛选；
- 分页列表展示标题、课程、类型、状态、审核/驳回原因、创建时间；
- 状态使用明显但简单的文本标签；
- 不提供前端伪造的编辑、撤回、删除或重新提交按钮。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/users/me/resources?status={status}&pageNo={pageNo}&pageSize={pageSize}` | 查询当前用户上传的资料和审核状态 |

**要展示的后端技术亮点**

- 当前登录用户由 JWT 上下文取得，前端不传 `userId`；
- 只查询本人数据，体现数据归属隔离；
- 审核状态生命周期及驳回、下架原因回显；
- 统一分页和 VO 输出，不直接暴露 Entity。

### 5.8 我的收藏页

**页面内容**

- 按收藏时间倒序的分页列表；
- 查看资料详情；
- 取消收藏按钮；
- 取消成功后从当前列表移除。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/users/me/favorites?pageNo={pageNo}&pageSize={pageSize}` | 查询当前用户有效收藏 |
| `DELETE /api/v1/resources/{resourceId}/favorites` | 取消收藏 |

**要展示的后端技术亮点**

- 收藏关系唯一约束和软状态复用；
- 收藏关系与资料 `favorite_count` 在同一 MySQL 事务内更新；
- Redis 收藏缓存位于事务提交之后，Redis 故障不回滚收藏主流程；
- 取消收藏实时联动排行榜热度 `-3`。

### 5.9 我的下载页

**页面内容**

- 分页展示资料标题、原文件名、文件大小、下载时间；
- 再次下载按钮；
- 不展示其他用户的下载记录。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/users/me/download-records?pageNo={pageNo}&pageSize={pageSize}` | 查询当前用户下载记录 |
| `GET /api/v1/download-records/{downloadRecordId}/file` | 使用已有下载记录再次获取文件流 |

**要展示的后端技术亮点**

- 当前用户数据归属隔离；
- 下载记录与文件读取分离；
- 文件接口校验下载记录归属，管理员可按后端规则访问；
- 文件以流式响应返回，不一次性包装进 JSON。

### 5.10 个人信息页

**页面内容**

- 用户 ID、用户名、昵称、角色和账号状态；
- 退出登录按钮；
- 管理员角色可显示“进入管理端”固定入口。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/users/me` | 获取当前登录用户信息 |
| `POST /api/v1/auth/logout` | 使当前 JWT 立即失效 |

**要展示的后端技术亮点**

- JWT 登录上下文；
- Redis `crp:auth:token:blacklist:{jti}` 黑名单；
- Token 剩余有效期与黑名单 TTL 对齐；
- 退出后再次使用原 Token 会被后端拒绝。

## 6. 管理员页面需求

### 6.1 审核管理页

**页面内容**

- 待审核资料分页列表；
- 按课程名、资料类型、上传者筛选；
- 通过按钮和可选审核意见；
- 拒绝按钮和必填拒绝原因；
- 审核记录抽屉或简单弹窗；
- 操作前确认，提交期间禁用重复点击；
- 操作成功后刷新当前列表。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/resources/pending-reviews` | 查询待审核资料 |
| `POST /api/v1/admin/resources/{resourceId}/audit-approvals` | 将待审核资料审核通过 |
| `POST /api/v1/admin/resources/{resourceId}/audit-rejections` | 将待审核资料审核拒绝 |
| `GET /api/v1/admin/resources/{resourceId}/audit-records` | 查询资料审核流水 |

**要展示的后端技术亮点**

- JWT 登录校验与 Service 层 `role = 2` 管理员权限兜底；
- 严格状态流转：只有待审核资料可以通过或拒绝；
- 更新 SQL 携带旧状态条件，防止并发审核重复生效；
- 资料状态更新和 `audit_record` 写入在同一事务中完成；
- 审核记录写入失败时回滚资料状态；
- 审核通过后在事务提交回调中初始化/更新热门资料榜，避免 Redis 与回滚事务冲突。

当前没有“管理员查看任意状态资料详情”的专用接口。待审核详情区域只能展示待审核列表已经返回的数据及审核流水，不能调用公开详情接口读取待审核资料，也不能在前端伪造缺失字段。

### 6.2 发布资料管理页

**页面内容**

- 复用简单搜索条件查询已通过资料；
- 查看公开详情；
- 下架按钮和必填下架原因；
- 操作成功后从当前公开列表移除。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/search/resources` | 查询当前公开的已通过资料 |
| `GET /api/v1/resources/{resourceId}` | 查看公开资料详情 |
| `POST /api/v1/admin/resources/{resourceId}/offline-records` | 将已通过资料下架 |
| `GET /api/v1/admin/resources/{resourceId}/audit-records` | 查看该资料的审核与下架记录 |

**要展示的后端技术亮点**

- 只有 `APPROVED` 状态可以流转为 `OFFLINE`；
- 下架状态更新与审核记录写入由事务保证；
- 下架完成后资料自动退出公开搜索、详情、收藏和下载链路；
- 事务提交后从 Redis 四周期热门资料榜移除，避免下架资料继续公开；
- 后端固定状态过滤形成真正的数据安全边界。

当前没有管理员“全部资料列表”接口，因此本页只管理可通过公开搜索查到的已发布资料，不实现拒绝、下架、删除资料的全状态后台列表。

### 6.3 排行榜运维页

**页面内容**

- 热门资料日榜、周榜、月榜、总榜；
- 热门搜索词日榜、周榜、月榜；
- 简单表格展示名次、标题/关键词和分数；
- “重建总榜”按钮、二次确认和结果提示；
- 不绘制趋势图、饼图或实时大屏。

**对应后端接口**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/rankings/resources/hot` | 查询热门资料排行榜 |
| `GET /api/v1/rankings/search-keywords/hot` | 查询热门搜索词排行榜 |
| `POST /api/v1/admin/rankings/resources/hot/rebuild` | 管理员手动重建 `all` 总榜 |

**要展示的后端技术亮点**

- Redis ZSet 实时排序与 MySQL 元数据补齐；
- 下载 `+5`、收藏 `+3/-3` 的行为热度联动；
- `all` 总榜缺失时按主键游标分页扫描 MySQL，只重建 `APPROVED` 资料；
- 使用临时 ZSet 构建并通过 `RENAME` 原子替换正式榜单；
- Redisson 看门狗读写锁协调总榜重建、实时写入与热度快照；
- 定时将总榜分数回写 `resource.hot_score`，供搜索排序和 Redis 故障降级；
- 周期榜只累计真实周期行为，不使用历史总量伪造日榜、周榜或月榜。

## 8. 首版明确不做的内容

### 8.1 不做复杂 UI

- 不做大屏、复杂动画、主题换肤、拖拽布局和像素级视觉设计。
- 不做复杂图表；排行榜、数量和状态使用表格、列表、数字和标签即可。
- 不做复杂移动端适配，只保证常见桌面浏览器和基础窄屏可用。
- 不做富文本编辑器、在线 Office/PDF 预览器和文件内容编辑。

### 8.2 不做复杂工程化

- 不拆微前端，不做多应用仓库和组件库发布体系。
- 不建立复杂领域模型、前端 Repository 层或大量代码生成器。
- 不为首版引入 SSR、PWA、离线缓存、Service Worker 或国际化体系。
- 不建设复杂自动化发布、灰度发布和前端监控平台。

### 8.3 不做复杂权限菜单

- 不实现后端返回菜单树、动态路由、按钮级权限配置和权限管理页面。
- 导航菜单固定；根据是否登录和 `role` 做简单显示控制。
- 不把前端路由守卫当成权限校验，管理员接口权限始终以后端结果为准。
- 不实现管理员用户管理、封禁、角色分配页面，因为当前后端没有对应业务接口。

### 8.4 不做复杂状态管理

- 不保存大规模全局业务状态。
- 不做跨标签页状态同步、离线队列和复杂请求缓存。
- JWT、当前用户和少量界面偏好可使用简单组合式状态或浏览器存储。
- 列表筛选、分页、弹窗等状态保留在各自页面内部。

### 8.5 不做后端尚未实现的功能

- 不做搜索建议、自动补全、中文分词、高亮和 Elasticsearch 专属交互。
- 不做管理员下载趋势、用户上传统计、运营大屏和复杂图表。
- 不做评论、举报、消息通知、积分、用户等级和资料推荐。
- 不做收藏夹分组、批量收藏或批量取消收藏。
- 不做 Refresh Token、多设备登录管理和登录限流展示。

- 不做临时下载地址过期倒计时，当前下载地址过期机制尚未实现。
- 不做已拒绝资料的在线修改后重新提交，因为当前没有对应接口。
- 不直接访问本地文件路径、数据库、Redis Key 或任何未公开的后端内部能力。

## 9. 建议演示流程

### 9.1 文件去重与审核闭环

1. 普通用户登录。
2. 选择文件，前端计算 MD5 并调用预检。
3. 未命中时上传物理文件；再次上传相同文件时展示秒传复用。
4. 提交资料元数据，进入待审核状态。
5. 在“我的上传”查看待审核状态。
6. 管理员在审核页通过或拒绝资料。
7. 普通用户刷新“我的上传”查看状态和原因。

该流程重点讲解：JWT、文件安全校验、MD5 去重、物理文件与业务资料解耦、补偿清理、审核状态机和事务审计。

### 9.2 搜索、收藏与公开性隔离

1. 搜索已审核通过资料。
2. 查看详情并收藏。
3. 在“我的收藏”查看记录并取消收藏。
4. 管理员下架资料。
5. 再次搜索或访问详情，验证资料不再公开。

该流程重点讲解：SQL 固定状态过滤、排序白名单、收藏幂等与事务、Redis Set 缓存、下架后的跨模块可见性控制。

### 9.3 下载限流与最终一致性

1. 在详情页创建下载记录并下载文件。
2. 短时间重复下载同一资料，验证允许下载但不重复计数。
3. 高频请求触发用户或 IP 维度限流。
4. 查看我的下载记录。
5. 在排行榜观察下载热度变化。

该流程重点讲解：Redis ZSet + Lua 滑动窗口、`SETNX` 去重、Redis Hash 增量、定时同步 MySQL、文件流和路径安全。

### 9.4 排行榜与运维能力

1. 查看日、周、月、总榜。
2. 通过下载、收藏、取消收藏观察热度变化。
3. 管理员手动重建总榜。
4. 再次查看总榜结果。

该流程重点讲解：Redis ZSet、MySQL 降级、临时榜原子替换、Redisson 看门狗读写锁、定时快照和最终一致性。

## 10. 首版验收标准

- 游客可以访问首页、搜索和已通过资料详情。
- 普通用户可以完成注册、登录、退出、上传、查看本人上传、收藏、取消收藏、下载和查看下载记录。
- 管理员可以查询待审核资料、审核通过、审核拒绝、下架资料、查看审核记录和手动重建总榜。
- 每个页面的请求均对应当前真实后端接口，不调用未实现接口。
- 页面能够正确处理统一 JSON 响应和文件二进制响应。
- `401`、`403`、`409`、`429` 等关键业务错误有清晰提示。
- 页面可直观看到待审核、已通过、已拒绝、已下架等状态变化。
- 演示者可以通过页面操作讲清 JWT、MD5 去重、审核状态机、事务、Redis 缓存、限流、去重统计、排行榜、分布式锁和最终一致性。
- 首版不因追求复杂 UI、复杂权限菜单、复杂状态管理或复杂图表而扩大开发范围。
