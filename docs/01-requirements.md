# 校园资料共享与智能检索平台需求文档

## 1. 项目背景

高校学生在学习过程中会产生大量课程资料，例如课件、实验报告、复习提纲、真题、笔记、课程设计参考资料等。现实中这些资料通常分散在班级群、网盘链接、论坛帖子或个人设备中，存在以下问题：

- 资料分散，查找成本高，重复上传严重。
- 资料质量不稳定，可能存在无效、重复、违规或与课程无关的内容。
- 资料缺少统一分类、标签、下载量、收藏量和热度等反馈信息。
- 管理员难以审核、下架和观察平台中的热门资料。
- 普通 CRUD 系统只能完成资料增删改查，无法体现搜索、审核、统计、风控、缓存和业务状态流转等真实后端能力。

本项目面向 Java 后端实习场景，目标是开发一个具备文件上传、资料审核、智能检索、下载统计、收藏、热门排行榜和接口限流能力的校园资料共享平台。系统以 Spring Boot 为核心，使用 MyBatis 或 MyBatis-Plus 操作 MySQL，使用 Redis 承担缓存、排行榜、限流、统计缓冲等真实业务场景，使用 JWT 完成登录认证与接口鉴权。后续可扩展 Elasticsearch、RocketMQ、对象存储、内容安全审核等技术栈。

## 2. 用户角色

### 2.1 游客

- 可以浏览已审核通过的公开资料列表。
- 可以搜索资料标题、课程名、标签、简介等公开信息。
- 不可以上传、下载、收藏和评论资料。

### 2.2 学生用户

- 可以注册、登录、退出登录。
- 可以上传课程资料。
- 可以查看自己上传资料的审核状态。
- 可以搜索、预览、下载、收藏、取消收藏资料。
- 可以查看自己的上传记录、下载记录和收藏列表。
- 下载、上传、搜索等高频操作受到限流规则约束。

### 2.3 管理员

- 可以审核学生上传的资料。
- 可以驳回资料并填写驳回原因。
- 可以下架已发布资料并记录下架原因。
- 可以查看热门资料排行榜、下载趋势和用户上传情况。
- 可以对违规用户或异常资料进行管理。

## 3. 核心业务流程

### 3.1 用户登录与鉴权流程

1. 用户提交账号密码。
2. 后端校验用户状态和密码。
3. 校验成功后签发 JWT。
4. 客户端后续请求携带 JWT。
5. 后端拦截器解析 JWT，识别用户身份和角色权限。
6. 用户退出登录时，可将 JWT 标识写入 Redis 黑名单，避免 Token 在过期前继续使用。

### 3.2 资料上传与审核状态流转流程

资料上传不是简单新增一条记录，而是一个带状态的业务流程：

1. 学生选择文件，填写课程名称、资料标题、资料类型、标签、简介等信息。
2. 后端校验文件大小、扩展名、MIME 类型、用户上传频率和必填字段。
3. 文件保存到本地文件系统或对象存储，数据库保存资料元数据。
4. 新资料初始状态为 `PENDING_REVIEW`，表示待审核。
5. 管理员审核资料：
   - 审核通过：状态变为 `APPROVED`，资料进入搜索范围，并可被下载。
   - 审核驳回：状态变为 `REJECTED`，记录驳回原因，用户可查看原因后重新上传。
6. 已通过资料如发现违规，管理员可执行下架：
   - 状态变为 `OFFLINE`。
   - 搜索结果中不再出现。
   - 普通学生不可下载。

建议状态流转如下：

```text
DRAFT/未提交 -> PENDING_REVIEW/待审核 -> APPROVED/已通过 -> OFFLINE/已下架
                                  \-> REJECTED/已驳回
```

### 3.3 资料搜索流程

1. 用户输入关键词，可附带课程、资料类型、标签、排序方式等过滤条件。
2. 后端先进行参数校验和搜索限流。
3. 初期使用 MySQL 实现基础检索：
   - 标题、课程名、简介、标签模糊匹配。
   - 仅检索 `APPROVED` 状态资料。
   - 支持按下载量、收藏量、发布时间、综合热度排序。
4. 搜索热词写入 Redis，用于生成热门搜索词。
5. 后续接入 Elasticsearch 后，通过统一的 `SearchService` 抽象切换搜索实现。

### 3.4 资料下载与统计流程

1. 用户请求下载资料。
2. 后端校验 JWT、用户状态、资料状态和下载权限。
3. 对下载接口执行 Redis 限流，防止恶意刷下载量或高频爬取。
4. 校验通过后返回文件流或临时下载地址。
5. 下载行为写入下载记录。
6. 下载计数优先写入 Redis，降低数据库写压力：
   - Redis Hash 记录资料下载增量。
   - Redis ZSet 维护热门资料排行榜。
7. 定时任务将 Redis 中的下载增量批量同步到 MySQL。

### 3.5 热门排行榜流程

1. 用户下载、收藏、浏览资料时，系统更新 Redis 中的资料热度分数。
2. 热度分可以由下载量、收藏量、浏览量、时间衰减共同组成。
3. 首页或后台排行榜直接从 Redis ZSet 获取 Top N。
4. 定时任务将热度快照落库，用于后台报表和长期趋势分析。

示例热度分：

```text
hot_score = download_count * 5 + favorite_count * 3 + view_count * 1 - time_decay
```

### 3.6 收藏流程

1. 学生点击收藏资料。
2. 后端校验资料是否存在且状态为 `APPROVED`。
3. 数据库保存收藏关系，避免重复收藏。
4. Redis 可缓存用户收藏资料 ID 集合，用于快速判断是否已收藏。
5. 收藏或取消收藏时同步更新资料收藏数和热度分。

### 3.7 管理员审核与运营流程

1. 管理员查看待审核资料列表。
2. 管理员可按课程、上传用户、资料类型、上传时间筛选。
3. 管理员查看资料详情和文件基础信息。
4. 管理员执行通过、驳回或下架。
5. 审核动作写入审核日志，保留操作人、操作时间、原状态、新状态和原因。
6. 管理员查看热门资料、热门课程、热门搜索词等运营数据。

## 4. 功能性需求

### 4.1 用户与认证模块

- 用户注册、登录、退出登录。
- 密码加密存储。
- JWT 认证与角色权限控制。
- 支持学生和管理员两类主要角色。
- 支持用户状态管理，例如正常、禁用。
- Redis 可用于登录态辅助管理、Token 黑名单和验证码缓存。

### 4.2 资料上传模块

- 支持学生上传文件资料。
- 支持配置文件大小限制、文件类型白名单。
- 支持资料标题、课程名称、资料类型、标签、简介等元数据。
- 上传成功后资料进入待审核状态。
- 上传频率需要限流，防止用户短时间批量提交垃圾资料。
- 文件存储层需要抽象，初期可使用本地存储，后续可切换 MinIO、阿里云 OSS、腾讯云 COS 等对象存储。

### 4.3 审核状态流转模块

- 管理员可以查看待审核列表。
- 管理员可以审核通过资料。
- 管理员可以驳回资料并填写原因。
- 管理员可以下架已通过资料并填写原因。
- 学生可以查看自己资料的审核状态和驳回原因。
- 所有审核动作需要记录审核日志。
- 状态变更需要校验合法性，例如已下架资料不能直接变为待审核。

### 4.4 搜索与筛选模块

- 支持按关键词搜索资料。
- 支持按课程、资料类型、标签、上传时间范围筛选。
- 支持按发布时间、下载量、收藏量、热度排序。
- 搜索结果只展示审核通过的资料。
- 搜索关键词写入 Redis，用于热门搜索词统计。
- 预留 Elasticsearch 接入能力，用于后续支持分词、高亮、相关性排序和搜索建议。

### 4.5 下载模块

- 学生登录后才能下载资料。
- 仅允许下载审核通过的资料。
- 下载前需要执行权限校验和限流校验。
- 下载成功后记录下载日志。
- 下载次数不能直接在每次请求中同步更新数据库，避免高并发下数据库写压力过大。
- 使用 Redis 缓冲下载计数，并由定时任务批量落库。

### 4.6 收藏模块

- 学生可以收藏和取消收藏资料。
- 支持查看个人收藏列表。
- 防止重复收藏。
- 收藏数变化影响资料热度分。
- 可使用 Redis Set 缓存用户收藏资料 ID，提升资料详情页中“是否已收藏”的判断效率。

### 4.7 热门排行榜模块

- 支持首页查看热门资料 Top N。
- 支持管理员查看热门下载资料、热门收藏资料、热门搜索词。
- Redis ZSet 维护实时排行榜。
- MySQL 存储排行榜快照或统计结果，便于长期分析。
- 排行榜分数应考虑下载、收藏、浏览、时间衰减等因素，避免老资料长期霸榜。

### 4.8 限流与风控模块

- 对登录、上传、搜索、下载等接口设置不同限流规则。
- 使用 Redis 实现限流，推荐滑动窗口或令牌桶。
- 限流维度包括用户 ID、IP、接口路径。
- 对下载接口增加防刷策略，例如同一用户短时间重复下载同一资料不重复增加热度。
- 可使用 Redis Lua 脚本保证限流计数和过期时间设置的原子性。

### 4.9 后台管理模块

- 管理员登录和鉴权。
- 待审核资料管理。
- 已发布资料管理。
- 下架资料管理。
- 热门资料查看。
- 用户上传统计查看。
- 审核日志查看。

## 5. 非功能性需求

### 5.1 安全性

- 密码必须加密存储。
- 使用 JWT 完成身份认证。
- 管理接口必须校验管理员角色。
- 文件上传必须校验扩展名、MIME 类型和文件大小。
- 下载接口必须校验资料状态和访问权限。
- 对高频接口执行限流，降低恶意请求风险。

### 5.2 性能

- 热门资料、热门搜索词和高频统计数据优先从 Redis 获取。
- 下载量、浏览量等高频计数通过 Redis 缓冲，定时批量同步到 MySQL。
- 搜索列表需要分页。
- 大文件下载避免一次性读入内存。
- 数据库表需要合理建立索引，例如资料状态、课程名、资料类型、创建时间、上传用户。

### 5.3 一致性

- 文件上传成功但数据库保存失败时，需要清理已上传文件。
- 数据库保存成功但文件存储失败时，不应生成有效资料记录。
- Redis 统计数据需要定时落库，并考虑任务失败后的补偿机制。
- 审核状态变更、搜索索引更新、排行榜更新之间需要明确最终一致性策略。

### 5.4 可维护性

- 按业务模块拆分代码，例如用户、资料、审核、搜索、下载、收藏、统计、限流。
- Controller 只处理请求参数和响应，不承载复杂业务逻辑。
- Service 层封装业务规则和状态流转。
- Repository/Mapper 层负责数据库访问。
- 使用统一异常处理、统一响应结构和参数校验。

### 5.5 可扩展性

- 文件存储使用接口抽象，方便从本地存储迁移到对象存储。
- 搜索能力使用接口抽象，方便从 MySQL 模糊查询升级到 Elasticsearch。
- 统计事件可抽象为领域事件，后续可通过 RocketMQ 异步消费。
- 审核能力可扩展人工审核、自动敏感词审核、第三方内容安全审核。
- 排行榜算法可配置不同权重，支持按课程、时间周期、资料类型生成榜单。

## 6. 核心难点

### 6.1 文件上传与资料元数据一致性

资料上传同时涉及文件存储和数据库元数据保存。需要处理文件保存成功但数据库失败、数据库成功但文件保存失败等异常场景。后续接入对象存储后，还需要处理临时文件、断点续传、文件访问权限和临时下载链接。

### 6.2 审核状态流转

资料审核不是普通更新字段，需要限制状态变化路径。例如待审核可以变为通过或驳回，通过后可以下架，但驳回不能直接变为通过。状态流转还会影响搜索结果、下载权限、排行榜统计和用户可见性。

### 6.3 搜索相关性与可演进设计

初期可使用 MySQL 实现基础搜索，但需要提前设计搜索服务抽象，避免后续接入 Elasticsearch 时大规模改造业务代码。搜索功能还要处理权限过滤、状态过滤、排序策略、热门搜索词统计等问题。

### 6.4 Redis 统计与数据库一致性

下载量、浏览量、热度分如果每次请求都直接更新 MySQL，会导致写压力过大。使用 Redis 缓冲可以提升性能，但需要考虑定时落库、失败重试、重复统计、数据丢失和排行榜快照等问题。

### 6.5 接口限流与防刷

上传、搜索、下载都可能被高频调用。限流不只是简单计数，还需要区分不同接口、不同用户和不同 IP。下载统计还要避免用户重复刷新导致下载量虚高。

### 6.6 权限与资源可见性

资料是否可见取决于用户角色、资料状态和操作类型。学生只能管理自己的上传记录，管理员可以审核和下架资料，游客只能查看公开资料。权限规则需要统一封装，避免散落在各个接口中。

## 7. 项目亮点

- 使用 Redis ZSet 实现实时热门资料排行榜，而不是从数据库实时聚合。
- 使用 Redis Hash 缓冲下载量增量，定时批量同步 MySQL，体现高频写优化。
- 使用 Redis + Lua 实现接口限流，覆盖上传、搜索、下载等真实高频场景。
- 使用审核状态机管理资料生命周期，体现业务规则和状态流转。
- 使用 JWT + 拦截器完成无状态认证，并支持 Token 黑名单。
- 文件上传与资料审核结合，形成完整的内容生产、审核、发布、消费闭环。
- 搜索服务预留 Elasticsearch 扩展点，项目可以从基础搜索演进到智能检索。
- 统计事件预留 RocketMQ 扩展点，后续可异步处理下载、收藏、浏览、审核通知等事件。
- 管理员后台不只是维护数据，还能观察热门资料和平台运营情况。

## 8. 如何避免成为普通 CRUD 项目

本项目不能只做“资料表的增删改查”。为了体现真实后端业务能力，需要围绕资料生命周期设计完整闭环：

### 8.1 从“数据操作”升级为“业务流程”

普通 CRUD 只关心新增、查询、修改、删除。本项目的资料上传后不能直接展示，而是进入待审核状态。审核通过后才能搜索和下载，被下架后又要从搜索、下载和排行榜中移除。每次状态变化都需要记录日志并影响多个模块。

### 8.2 从“同步数据库更新”升级为“高频统计架构”

下载量、浏览量、热度分属于高频变化数据。项目使用 Redis 作为统计缓冲层和排行榜计算层，定时批量同步数据库，体现缓存、异步落库和最终一致性设计。

### 8.3 从“列表查询”升级为“检索能力”

资料搜索不仅是分页查询资料列表，还要支持关键词、课程、类型、标签、排序、热门搜索词和后续 Elasticsearch 扩展。搜索结果还必须结合审核状态和权限过滤。

### 8.4 从“简单接口”升级为“安全与风控”

上传、下载、搜索接口都需要限流。下载接口需要防刷下载量，上传接口需要防止垃圾资料灌入，登录接口需要防止暴力尝试。这些能力让项目更贴近真实线上系统。

### 8.5 从“单模块项目”升级为“可演进平台”

项目按用户、资料、审核、搜索、下载、收藏、统计、限流等模块拆分，并为 Elasticsearch、RocketMQ、对象存储和内容审核服务预留扩展点。这样后续可以逐步增加技术栈，而不是推翻重写。

## 9. 可扩展方向

### 9.1 Elasticsearch 智能检索

- 支持中文分词。
- 支持搜索高亮。
- 支持相关性评分。
- 支持搜索建议和拼写纠错。
- 支持课程、标签、资料类型等多条件聚合。

### 9.2 RocketMQ 异步事件

- 下载事件异步统计。
- 收藏事件异步更新热度。
- 审核通过事件异步创建搜索索引。
- 资料下架事件异步删除搜索索引。
- 审核结果异步通知用户。

### 9.3 对象存储

- 将本地文件存储迁移到 MinIO 或云对象存储。
- 支持临时下载 URL。
- 支持文件访问权限控制。
- 支持文件去重和秒传。

### 9.4 内容安全与质量评分

- 敏感词检测。
- 重复资料检测。
- 文件病毒扫描。
- 用户举报机制。
- 资料质量评分和推荐排序。

### 9.5 积分与成长体系

- 上传通过后获得积分。
- 下载资料消耗或获得积分。
- 优质资料作者获得额外奖励。
- 用户等级影响上传频率或下载额度。

## 10. 建议的核心模块边界

```text
user        用户、角色、JWT 鉴权
resource    资料元数据、文件上传、资料详情
review      审核状态流转、审核日志
search      搜索、筛选、热门搜索词
download    下载权限、下载记录、下载计数
favorite    收藏、取消收藏、收藏列表
ranking     热门资料、热度计算、排行榜快照
rate-limit  Redis 限流、Lua 脚本
storage     本地文件存储、对象存储扩展
common      统一响应、异常处理、参数校验、工具类
```

## 11. 第一阶段最小可落地范围

为了保证项目能从零开始逐步完成，第一阶段建议优先实现以下闭环：

1. 用户注册、登录、JWT 鉴权。
2. 学生上传资料，资料进入待审核状态。
3. 管理员审核通过或驳回资料。
4. 学生搜索已通过资料。
5. 学生下载资料，下载量写入 Redis。
6. Redis ZSet 展示热门资料排行榜。
7. Redis 限制上传、搜索、下载接口访问频率。
8. 定时任务将 Redis 下载量同步到 MySQL。

完成以上内容后，项目已经具备文件处理、状态流转、检索、缓存、排行榜、限流、统计同步和权限控制，不再是普通 CRUD 项目。
