### IMP-001 默认 JWT 密钥可生成有效管理员 Token

- **严重等级 / 模块 / 类型**：P1 / 认证与配置 / 密钥管理、垂直越权
- **当前行为**：未设置 `JWT_SECRET` 时使用仓库公开的开发默认值；JWT 中的 `role` 直接参与管理员权限判断。
- **代码证据**：`campus-resource-platform/src/main/resources/application.yaml` 的 `jwt.secret` 默认值为 `campus-resource-platform-dev-secret-change-me`；`JwtUtils` 仅检查长度；`JwtAuthenticationInterceptor` 从 Token 建立 userId/role；审计环境确认 `JWT_SECRET` 未设置（未读取或输出任何密钥值）。
- **触发条件 / 实际影响**：部署遗漏环境变量时，攻击者可用公开默认值签发任意 userId、role=2 Token，调用审核、下架和排行榜重建等管理员能力。
- **根本原因**：开发兜底值进入可运行配置，启动时没有拒绝弱/默认密钥。
- **推荐方案**：移除可用默认值；启动时校验密钥存在、长度和非已知默认值；由密钥管理系统注入并建立轮换策略。
- **可能涉及的文件**：`application.yaml`、`JwtUtils`/认证配置、启动配置测试、部署文档。
- **实施成本 / 修改风险**：低 / 中。
- **验收标准**：未提供密钥或使用已知默认值时应用拒绝启动；随机伪造管理员 Token 被拒绝；轮换前后旧 Token 行为符合明确策略。
- **数据库变更 / 公开接口**：否 / 否。

### IMP-002 已禁用用户和旧管理员 Token 不会立即失效

- **严重等级 / 模块 / 类型**：P1 / 认证与权限 / 水平与垂直权限状态
- **当前行为**：拦截器只验 JWT 和 Redis 黑名单，直接信任签发时的 userId、role；绝大多数请求不查询当前用户状态或角色。
- **代码证据**：`JwtAuthenticationInterceptor` 60-79 行；`AuditServiceImpl.requireAdmin` 234-239 行和 `AdminRankingServiceImpl` 28-33 行只检查上下文角色；仅 `UserServiceImpl.getCurrentUser` 31-41 行查库检查用户状态。

- **根本原因**：JWT 没有用户状态版本，权限边界没有以当前账户状态为准。
- **推荐方案**：在认证边界验证当前用户，或引入 token-version/status 缓存；角色/状态变化时统一吊销旧版本 Token。
- **可能涉及的文件**：认证拦截器、用户 Mapper、Redis Key、JWT 服务、管理员权限测试。
- **实施成本 / 修改风险**：中 / 中。

- **数据库变更 / 公开接口**：通常否 / 否。

### IMP-004 下载记录可重放并绕过资料下架和限流

- **严重等级 / 模块 / 类型**：P1 / 下载与审核 / 授权、重放、状态约束
- **当前行为**：downloadRecordId 无过期、无消费标记，可无限 GET；取流只检查记录归属和文件状态，不重验资料 `APPROVED`，文件 GET 也不再次限流。

### IMP-005 任意登录用户可引用其他用户已上传的 fileId

- **严重等级 / 模块 / 类型**：P1 / 文件与资料 / 水平越权、资源归属
- **当前行为**：资料创建只检查 fileId 对应文件为 NORMAL，不验证上传者、上传会话或当前用户是否持有该文件引用；MD5 预检还会返回全局 fileId。
- **代码证据**：`ResourceServiceImpl.create` 75-100 行；`FileServiceImpl.checkByMd5AndSize` 返回 fileId；`file_info` 未保存上传者关系，创建链路没有 user-file 授权校验。
- **触发条件 / 实际影响**：用户枚举、日志获知或通过相同 MD5 预检取得另一用户的 fileId 后创建资料；私有上传内容可能被他人包装并提交公开审核。
- **根本原因**：全局物理去重 ID 被直接当成业务授权凭据，缺少用户上传/引用关系。
- **推荐方案**：建立 user-file 上传授权关系或短期用户绑定引用证明；资料创建消费当前用户的授权，而非仅信任数字 fileId。
- **可能涉及的文件**：文件/资料 Service、DTO、持久层、SQL 迁移、权限测试。
- **实施成本 / 修改风险**：高 / 高。
- **验收标准**：用户不能用未授权 fileId 创建资料；同文件秒传仍可安全复用物理内容；授权证明不可被其他用户重放。
- **数据库变更 / 公开接口**：很可能需要 / 可能调整上传或创建参数。
- **当前状态**：APPROVED（用户于 2026-07-15 明确要求实施）。

### IMP-006 并发创建可绕过资料重复提交校验

- **严重等级 / 模块 / 类型**：P1 / 资料与 MySQL / 并发、幂等
- **当前行为**：事务内先 COUNT 当前用户同 fileId 的活动资料，再普通 INSERT；表上没有覆盖该业务不变量的唯一约束。
- **代码证据**：`ResourceServiceImpl.create` 92-100 行；`ResourceMapper.xml` SQL ID `countActiveByUploaderAndFileId` 285-292 行；`sql/init.sql` 89-95 行只有普通索引；现有数据库测试只验证顺序重复。
- **触发条件 / 实际影响**：同一用户并发提交相同 fileId，两次查询都在任一 INSERT 前完成；生成多条待审核资料、重复审核和重复公开内容。

- **实施成本 / 修改风险**：中到高 / 中。
- **验收标准**：并发 10 次相同业务键请求，数据库最多一条有效资料，其余返回一致语义。
- **数据库变更 / 公开接口**：建议需要 / 结构不变，冲突语义可能明确。
- **当前状态**：PROPOSED。

### IMP-012 MySQL 集成测试可能误删非测试库表

- **严重等级 / 模块 / 类型**：P1 / 后端测试与 MySQL / 测试隔离、数据安全
- **当前行为**：测试允许 `MYSQL_TEST_URL`/普通 MySQL 账号指向任意库，并在每个测试前执行包含无条件 `DROP TABLE` 的脚本，没有库名保护。
- **代码证据**：`AuditServiceDatabaseIntegrationTest` 41-56 行使用真实 MySQL、`Replace.NONE`、外部 URL 和 `BEFORE_TEST_METHOD` SQL；48-50 行可回退普通账号；`src/test/resources/sql/resource-db-test-schema.sql` 1-5 行删除五张表。

### IMP-040 构建工具链校验与版本基线不统一

- **严重等级 / 模块 / 类型**：P3 / 后端构建 / 可重复性、供应链
- **当前行为**：系统 `java` 为 21，但 Maven Wrapper 实际使用 JAVA_HOME 的 24，目标为 17；Wrapper 固定 Maven URL 但没有 `distributionSha256Sum`。
