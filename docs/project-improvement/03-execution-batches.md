# 建议执行批次

> 以下批次仅是审计建议，不代表获得实施许可。每个批次按生产代码不超过 8 个文件规划，可独立测试和回滚；实际开始前仍需在 `04-review-decisions.md` 获得用户明确决定。
>
> 字段约定：每个批次的“回滚方式 / 顺序”同时给出该批次内部的建议执行顺序；文末“建议总顺序”给出批次之间的顺序。

## BATCH-01：JWT 密钥与实时账户权限

- **目标 / 问题 ID**：关闭 Token 伪造和旧权限继续生效；IMP-001、IMP-002。
- **适合一起处理**：都位于认证边界，需共同确定启动密钥校验、用户状态和 Token 撤销语义。
- **前置依赖**：密钥注入/轮换方式；账户状态变化来源；Redis 故障时权限策略。
- **预计修改范围**：认证配置、Jwt 工具、拦截器、用户查询/Redis Key，生产代码约 4–6 个文件。
- **数据库 / Redis / 接口兼容性**：数据库通常无；Redis 可能新增 token-version；接口结构不变，旧 Token 可能失效。
- **测试范围**：默认密钥启动失败、伪造 Token、禁用/降权/删除后旧 Token、Redis 异常、管理员接口。
- **回滚方式 / 顺序**：回滚认证变更并恢复旧密钥配置；先部署新密钥与兼容验证，再启用强校验。

## BATCH-02：MySQL 测试库安全隔离

- **目标 / 问题 ID**：保证测试 DDL 永不触碰非测试库；IMP-012。
- **适合一起处理**：单一测试基础设施问题，可独立交付。
- **前置依赖**：选择 Testcontainers、临时 schema 或受限专用库。
- **预计修改范围**：仅测试类、测试配置和测试 DDL/容器文件，0 个生产代码文件。
- **数据库 / Redis / 接口兼容性**：仅测试数据库；Redis 无；公开接口无。
- **测试范围**：危险库名在 DDL 前失败、专用库全量 113 tests、并行/清理验证。
- **回滚方式 / 顺序**：回滚测试基础设施提交；应在任何新增 CI 前完成。

## BATCH-03：管理员待审核详情与文件预览

- **目标 / 问题 ID**：让管理员可核验待审核实际内容；IMP-003。
- **适合一起处理**：审核详情与受控预览是同一授权场景。
- **前置依赖**：是否允许下载原文件、在线预览格式、审计日志规则。
- **预计修改范围**：审核 Controller/Service/VO、文件读取协作者，生产代码约 4–6 个文件。
- **数据库 / Redis / 接口兼容性**：均无强制影响；新增管理员接口，不破坏现有接口。
- **测试范围**：管理员成功、普通用户/游客越权、文件缺失/路径异常、并发状态变化。
- **回滚方式 / 顺序**：移除新增接口即可；先完成权限测试再开放路由。

## BATCH-04：下载票据、状态与计数生命周期

- **目标 / 问题 ID**：修复重放、下架绕过和提前成功计数；IMP-004、IMP-008。
- **适合一起处理**：两项都源于下载记录同时承担审计和凭证，拆开会形成过渡不一致。
- **前置依赖**：下载成功定义、票据 TTL/次数、客户端中断口径。
- **预计修改范围**：下载 Controller/Service/Entity/Mapper、审核联动，生产代码约 5–8 个文件。
- **数据库 / Redis / 接口兼容性**：可能新增状态/票据存储；Redis 可保存短票据；下载 URL/状态语义变化。
- **测试范围**：未 GET、文件失败、首次/重放、过期、下架、限流、并发消费、客户端兼容。
- **回滚方式 / 顺序**：保留旧字段兼容窗口，按票据版本切换；回滚时恢复旧下载路由。

- **回滚方式 / 顺序**：新增关系先回填再强制校验；回滚关闭强制校验并保留关系表。
